# 资料库与解读

## 工作目录

资料库独立于技能包，优先复用用户已有组织方式。没有现成结构时使用：

```text
writing-workspace/
  project-index.md
  projects/
    项目名称/
      overview.md
      material-index.json
      originals/
      summaries/
      images/
  requirements/
  examples/
  drafts/
```

`originals` 保存需要稳定留存的上传副本，已有稳定来源也可仅索引，不重复搬运大视频。`summaries` 保存项目解读与专题，`images` 保存选用的处理后图片。模板和参考例子与事实材料分别索引；用户不必迁移已组织好的文件。运行环境不能持久保存时，交付可下载资料包供下次重新提供，不声称跨会话自动记忆。

先读 `project-index.md` 定位项目，再读 `overview.md` 建立全貌，按需求读取专题及对应原始片段。若知识库仅返回局部检索片段，尝试读取完整项目全貌；无法取得时说明当前覆盖，不能称已理解完整项目。

## 材料身份与来源

材料索引可用随包 JSON 模板，也可用等效表格。每份材料至少记录：编号、所属项目、角色、文件或资源位置、版本/日期、阅读范围、解读入口、脱敏状态。需要核对的主张保留页码、工作表/单元格或片段时间；来源无精确时间时使用片段描述，不编造时间戳。

角色包括 `requirement`、`example`、`fact`、`summary`、`draft`。混合文档按章节分别记录，不能将整份模板里的示例内容视为事实。`draft` 是写作产物，除非其中具体事实经原材料或用户确认，否则不参与事实反向补全。

汇总记录它覆盖的材料编号与版本、覆盖范围、生成方式（人工/模型/混合）、人工确认状态及未覆盖部分。用户对事实的直接补充也是来源，记录其确认内容，不扩展为对整个资料库的确认。

## 复用判断

| 当前情况 | 动作 |
| --- | --- |
| 已有解读覆盖所需内容，材料未发生相关变化 | 直接复用；不重新全量转录、抽帧或逐页总结 |
| 用户明确认可现有汇总，原件暂不可得 | 按其确认范围使用，保留来源性质；不要求为使用而重做汇总 |
| 汇总未说明覆盖，但内容与当前材料能对应 | 轻量确认范围，必要时抽查关键位置；不一律推倒重来 |
| 本次只需要未整理的某个细节 | 定位该来源局部补读，并在授权整理范围内补入专题 |
| 新材料与旧内容冲突 | 用户明确纠正的据此更新；其他冲突并列具体差异，找相关来源确认 |
| 仅新增无关附件或文件格式变化 | 不重新解读其他材料 |

文件哈希可用于发现副本或版本变化，但哈希变化不自动触发整个项目重做。更新报告集中说明变化内容和受影响的结论。

## 多模态阅读

- 文档：读清正文、表格、图注及条件；方法规定、会议建议、实施事实分别表达。
- 表格：读取工作表、表头、单位、公式/结果以及口径说明。只看截图不能声称已核对隐藏工作表或完整公式。
- 图片：查看实际画面并结合说明，辨别原型、运行界面、示意图及演示数据。不要仅用 OCR 代替图表理解。
- 视频：优先利用已有字幕、转录、笔记和关键帧。首次处理时先建立讨论时间线，再按场景切换、系统演示和争议位置查看画面。按实际需要补帧，不固定截图数量。
- 缺字幕时使用实际可用且符合用户材料使用范围的 ASR；记录自动转录身份。未取得画面时只称“音频/转录解读”，不称已结合视频画面。没有相应工具时明确缺少哪项能力，保留已完成工作，不自行安装或上传到未获授权的服务。
- 两种材料描述同一过程时组合成连贯说明；不把演示截图、会议口述、预测测算混写成实际验收或实现的收益。

阅读记录简洁记录实际处理的文字范围和查看的画面，不因生成了抽帧清单就声称所有图片已逐张看过。大材料按自然主题分批读取，合并时检查跨段衔接、主体与时序。

## 项目全貌与审核

项目全貌先讲目标与背景，再解释原来的工作方式、问题、环境约束、各场景的处理过程和关联、参与方职责、结果与当前状态。保留主线的因果和必要业务细节，不以极短摘要替代可理解的项目说明。大量细节放专题并提供入口。

提炼实际做法可以归纳，不得补造缺失动作。确有依据的价值直接表述；不添加为了显得完整的数字、人员、验收流程或成效。

新项目初稿交用户核对：事实是否正确、理解是否完整、脱敏处理是否合适。明确确认后记录状态。用户已同意使用的旧汇总不重复请求整体验收。补充材料时仅核对变化；如果用户只要求阅读说明，就交付说明，不额外启动文档写作。
